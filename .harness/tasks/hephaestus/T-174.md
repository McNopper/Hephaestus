BUG (process class, found while draining the in-review queue 2026-11-17): the tick's step 1 is `task_readiness ... take only this stage's tickets` and readiness reports no-stage tickets as NOT_APPLICABLE, so step 3 (IN-REVIEW -> VERDICT) never sees a STAGELESS in-review ticket - while the arm-time prompt template (ticker-setup.ps1) independently enumerates `(3) IN-REVIEW tickets of this stage get their engine verdict`. Evidence at registration: 12 stageless tickets sit in in-review with zero ticker-v verdicts in their history (T-087..T-092 docs de-fleet lane, U-009, U-052, U-075, U-102, U-104, U-105), while every staged in-review ticket drains. AGENTS.md already presupposes unstaged tickets ARE verdicted (the UNCLEAR bullet: 'an unstaged ticket stays in in-review with the doubt as a comment'). So the engine has no lane to finish them - they wait forever, each carrying 'done is never self-assessed'. Fix the class, not the instance: a once-per-pass STAGELESS verdict lane in the stage-pipeline skill AND the tick prompt template (both carriages - the prompt enumerates steps independently of the skill), then re-arm so the LIVE schedule carries it. This ticket is deliberately STAGELESS (stage: null) so the new lane verdicts it - dogfood, not exception.
