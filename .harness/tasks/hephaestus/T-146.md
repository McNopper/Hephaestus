Every Eclipse start logs (workspace .metadata/.log, latest 2026-11-16 14:00): BundleException in org.eclipse.cdt.core.CCorePlugin.start caused by IllegalStateException: The instance data location has not been specified yet (DataArea.assertLocationInitialized), reached from EclipseLazyStarter.postFindLocalClass - i.e. our OSGI-INF/CdtProjectContext.xml declares immediate=true, so Felix SCR activates it at framework start; constructing CdtProjectContext class-loads org.eclipse.cdt.core.model.* which lazy-starts org.eclipse.cdt.core before IDEApplication has set the instance location. The component instantiation then dies with the secondary NPE (getConstructor() null). Pre-existing in 6+ historical logs; the IDE otherwise runs. Fix per the DS contract: drop immediate=true (delayed configuration - the service registration stays eager, activation happens on first getService through core's LAZY ProjectContext tracker, by which time the instance area is set), document the contract in the XML, and pin it with a regression test reading the component descriptor.
