Owner question 2026-11-18: "Should sessions and terminals be visible in the server browser?" Answer: yes, as read-only inventory. Rationale: the Server browser is the 'what does this server host' surface; in v2, sessions and shell/PTY terminals are server-hosted resources, and omitting them repeats the no-hidden-work complaint. T-038's enumeration stopped at four classes (MCP servers, agents, skills, providers) - this extends it to six. Boundary: inventory + live state badges ONLY in the browser; transcripts stay in Session Details, terminal output in a standard Eclipse console (ConsoleManager/MessageConsole pattern), work orchestration in the Board/tickers. Hierarchy: server -> sessions (state badge running/idle/background; v2 parentID subagent children, collapsed) -> terminals/console tasks (running/finished, live). v2 realities: session STATE is global per user - scope by the server's ?directory= and present as 'visible through this server', never owned by it; event streams are per-process - the inventory reuses already-flowing events and the busy-status maps (expand-to-poll, no new poll loops).
