Found during the T-040 live acceptance pass (test-requirements), 2026-11-17. AC1 of T-040 ("Agent Tools console exercised live in Eclipse with an agent-driven build/run/debug") could NOT be exercised: the eclipse-build MCP endpoint that feeds the Agent Tools console never comes up in the deployed Eclipse, so no eclipse-build tool invocation can reach McpDispatcher/ToolInvocationHub/AgentToolsConsole.

OBSERVED (all black-box, reproducible):
1. Deployed Eclipse C:\eclipse-cpp (dropins 0.4.1-SNAPSHOT, 2026-11-17 08:48) launched repeatedly today against workspace C:\Development\workspace-cpp (15:34:09, 15:41:30, 15:45:38, 15:51:05, 15:55:28 local) plus two throwaway-workspace runs via eclipse/debug-launch.ps1 (15:56, 15:58). In every run: NO 'eclipse-build MCP listening on http://127.0.0.1:<port>/mcp' line in the workspace log (C:\Development\workspace-cpp\.metadata\.log - every logged session from 2026-11-16 11:58 through 2026-11-17 15:51, incl. .bak_0.log - zero matches for 'listening'/'ide.mcp').
2. Process listeners owned by eclipse: only the OpenCode Chat web bridge (127.0.0.1:52930, GET / -> title 'OpenCode Chat', /mcp -> 404) - no MCP Streamable HTTP endpoint ever listened.
3. The opencode service never received the registration: GET /api/mcp?location[directory]=C:/Development/GitHub/Hephaestus returns only [pixellab, tasks] (checked 2026-11-17 14:34Z and repeatedly after); unscoped /api/mcp shows only pixellab. So PUT /api/experimental/mcp/eclipse-build (HttpOpencodeClient.registerMcp) never succeeded - eclipse-build is invisible to every agent session.
4. Core ran fine in the same runs (workspace log: '[opencode service] attached to the shared background service at http://127.0.0.1:28894', com.opencode.ide.core INFO) - the OpencodeConnection service the registration component binds IS present, yet no endpoint and no registration followed.

HYPOTHESIS (needs verification, not yet proven): the DS chain stalls at McpInfo. McpServiceComponent is immediate="false" (delayed) and its ONLY consumer in the whole source tree is core's McpRegistrationComponent (reference mcp cardinality 0..1, policy dynamic, OSGI-INF/McpRegistrationComponent.xml); the SCR resolves an unsatisfied optional reference against REGISTERED services, and a delayed component only registers when its service is requested - i.e. nobody ever requests McpInfo, so activate() (which starts McpHttpServer and logs the 'listening' line) never runs, getEndpointUrl() stays null, and McpRegistration.registerIfNeeded returns early on the null URL (McpRegistration.java:34-45).

REPRO: deploy (eclipse/deploy-dev.ps1), start C:\eclipse-cpp\eclipse.exe, wait >=2 min, then (a) grep the workspace .metadata/.log for 'listening' (no match), (b) Get-NetTCPConnection owned by the eclipse process (no MCP port), (c) opencode api get "/api/mcp?location[directory]=C:/Development/GitHub/Hephaestus" (no eclipse-build).

IMPACT: blocks T-040 AC1 / U-009 AC4 - the Agent Tools console can never show an agent-driven build/run/debug because the traffic source is dead. INTEGRITY note: this is an observation-backed finding; the DS-cycle diagnosis above is a hypothesis to confirm (e.g. OSGi console 'ss'/'services' or Felix SCR debug logging) before fixing - the likely fix shape is making the endpoint component eager (immediate="true") or adding a real consumer that requests McpInfo, but the fix belongs to whoever picks this ticket up.
