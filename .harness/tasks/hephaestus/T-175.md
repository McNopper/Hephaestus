Owner directive 2026-11-17: 'direct improvement, as the tickets are related always to a stage, for the future, encode the stage in the ticket name.' The store owns the tag: a staged ticket's title carries a leading `[stage] ` prefix so the stage is visible wherever the name shows up (chat listings, board, task_list output, comments) - not only in the frontmatter the reader has to open the file to see.

Design (single seam in TaskStore, applied at every title/stage write):
- create(project, spec, stage): title = `[stage] ` + title (strip any existing known-V-stage tag first -> idempotent, tag-exclusive).
- update case 'title': re-applies the ticket's CURRENT stage tag (a rename cannot drop it).
- update case 'stage' (the Board owner-override path - the actor verbs reject stage writes): the tag FOLLOWS the stage move; clearing the stage strips it.
- stageless tickets never carry a V-stage tag; a title that is nothing but a tag is never emptied (preserved when there is no stage to restate).
- Only known VStages tags are stripped - a caller's own `[WIP] ...` bracket survives, right of the stage tag.
- Existing tickets are NOT rewritten (the directive says 'for the future'); they gain/lose the tag on their next title/stage write.

Inherited by every creation path for free (they all go through create): ticker division children, pairing/acceptance instances, GoalIntake goal tickets, PM import, chat task_create.
