OWNER DIRECTIVE (chat, 2026-11-26, verbatim): 'also, review and consolidate the markdown documents. should be non-agentic style and readable for humans. the important information needs to be in and aligned with the code.'

This is a documentation-library review + consolidation, distinct from T-218/T-227 (which fixed specific false claims). Scope: every tracked *.md EXCEPT the task store (.harness/** is data, not prose; _archive/** is history) and the contract-test-pinned carriages' literal text (see constraints).

THREE REQUIREMENTS, from the owner's words:
1. REVIEW + CONSOLIDATE: map every document, find the redundancy clusters (same content told 3-5 times across design/requirements/system/architecture/tests records), the near-dead ones (RETIRED-marked, superseded), and the ones whose 'important information' is buried in agent-protocol narration. Propose merges - a merged document must LOSE nothing that is important, only duplication and process narration.
2. NON-AGENTIC, HUMAN-READABLE: prose that a person reads top-to-bottom understands - not instruction-speak addressed to an agent ('the worker must quote', 'report back to the coordinator'), not AC/ticket archaeology as the organizing principle, not status dashboards pretending to be docs. Keep the About-this-document convention (it helps humans too) but write for a reader, not a dispatcher.
3. IMPORTANT INFORMATION IN AND ALIGNED WITH CODE: anything a human needs to operate/understand the harness must be present AND true against the source (the T-210..T-227 sweeps established the code/store as the status source; do not reintroduce stale claims while rewriting).

METHOD (phases): (A) AUDIT - a document map with per-file: purpose, audience, live/historical/retired, overlap cluster, importance, rewrite/merge/keep/retire disposition; (B) EXECUTE the dispositions in lane-sized tickets with reviews; (C) GATE - lint 0, no broken cross-doc links, contract-test literals intact, code claims spot-verified.
