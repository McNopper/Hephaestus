BASIS ARTIFACTS (governing definitions): docs/acceptance-run-system.md (the acceptance-run system definition: four major parts - task store, per-stage ticker, goal-driven worker subagents, engine review pass + quality gate - with per-part responsibilities, inter-part interfaces, and the per-D-point evidence flows + D-point map) and, for scope context, docs/acceptance-stage-pipeline.md (the run's requirements: demonstration contract D-1 stationary fulfillment / D-2 division + linking / D-3 engine verdict, evidence list, pass/fail criteria) + docs/design-stage-pipeline.md (the U-111 arc's pipeline design: model, tick, fulfillment, verdict). GOAL FOR THE ARCHITECTURE AGENT: produce docs/acceptance-run-architecture.md - the architecture OF the acceptance run: the component/module structure of the four parts, the explicit dependency rules between them (the store as the only shared substrate; tickers and workers never link directly - all coordination is store-mediated; the engine review pass as the only done authority, structurally not conventionally), and the traceability of every D-point's evidence flow through the architecture's components. Where docs/design-stage-pipeline.md already fixes the structure, the doc records the mapping and the pass-through rationale as its artifact instead of inventing new structure. File lane: docs/acceptance-run-architecture.md only. Record the artifact and set in-review - never done (the engine's review pass is the only done authority).
