Crash class diagnosed 2026-11-15 after both ticker-v passes died mid-scan: McpDispatcher.handle converts RuntimeExceptions to -32603, but java.lang.Error escapes (NoSuchMethodError after a jar swap mid-flight, StackOverflowError, OOM) - it propagates through StdioServer.serve (no try/catch around dispatcher.handle) and main(), and the JVM exits code 1. Trigger: concurrent multi-process store access on Windows (the ticker pass firing while other sessions read/write - EPERM rename contention is visible in the service log). Fix: StdioServer.serve catches Throwable per request, answers a JSON-RPC -32603 error response, keeps the loop alive; the parentAlive probe is likewise defensive. PROVENANCE (Build mode): fixed directly under the owner's active Build override before this ticket existed; the regression test (StdioServerTest.aThrowingHandlerDoesNotKillTheLoop) is the verdict authority.
