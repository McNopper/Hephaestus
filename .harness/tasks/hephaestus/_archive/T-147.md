Owner report 2026-11-16: 'in the tui, i get the compaction displayed, here not ... it just says compacted, while it is obvious it is doing more'. Ground truth: the v2 message carries status/reason/summary/tokens/native (opencode.db session_message type=compaction, summary = the full markdown context summary). The TUI (packages/tui routes/session/index.tsx CompactionMessage) renders a divider row - rule lines around a spinner or X, the label 'Compaction' (or 'Provider compaction' when native), optional 'cancelled' and '<N> in / <N> out' usage suffixes - and the whole summary as markdown below it; while running it streams session.compaction.delta into that row (started/delta/ended/failed events). The Eclipse panel instead (a) reduced history compaction rows to a synthetic one-line notice (T-145 marker) and (b) after POST /compact appended a hardcoded notice - the summary content was never displayed, live or on reload. Fix = TUI parity end to end: deserializer keeps the compaction payload (summary/error/providerNative + lifecycle status in the finish slot, no fake text part), historyRows emits a role=compaction row (status, native flag, text = summary or failure message, usage), chat.js renders the TUI divider row (spinner while running, X on failure, cancelled suffix, usage suffix, markdown body), and the controller subscribes to session.compaction.started/delta/ended/failed so a live /compact streams summary progress and finalizes with usage; POST success seeds the running row only when no compaction event was seen (idempotent start - no duplicate row). T-145's notice-row mechanism (appendNoticeRow / role=notice) is superseded by the compaction row and removed with its checks.
