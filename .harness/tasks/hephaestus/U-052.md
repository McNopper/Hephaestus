TaskStore.recordInvalidations (TaskStore.java:1296-1310) writes 'inputs changed:' history markers on STALE verdicts, but only RecordInvalidationsTest calls it: no production path, no tool, and no ticket carries such a marker. Call it from the production readiness tick (or task_readiness), idempotently. D-003 may refine which upstream writes count. Tests first where behavior changes; write the store only via task_* tools; quality gate green (cd eclipse; .\build.ps1 verify -Pquality) before in-review.

AMENDED per decision D-003 (2026-10-07): STALE compares an inputs_changed_at stamp (updated ONLY when status/stage/artifacts/epic/role change) instead of updatedAt - comments and bookkeeping no longer invalidate completed downstream work (the W-006 incident). recordInvalidations writes the 'inputs changed:' marker at that point. Test: a comment on an upstream does NOT stale its done downstream; a stage change DOES.
