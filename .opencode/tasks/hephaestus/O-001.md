Vision (from the product owner, 2026-09-15): "When I open the repo with opencode, the MCP servers, agents and so on are all set up. Similar behaviour for Eclipse. If I somehow open the Hephaestus repo, there is an Eclipse project in the root or something similar."

Today the parity is partial: a spawned opencode server whose working directory is the repo already loads that repo's `.opencode/` agents, skills and `opencode.json` MCP servers (chat-side parity exists via ProjectContext + the repo-root preference fallback). What is NOT repo-driven:

1. **Manual preferences**: connection working directory and tasksRoot are workspace preferences with defaults - the end user must know to set them. They should be DERIVED from the opened repo, preferences only as override.
2. **Nothing visible**: the repo's MCP servers/agents are invisible in the IDE (only reachable through chat tools/list).
3. **No one-click "open repo"**: the natural carrier would be a repo-root Eclipse project (a `.project` with an `com.opencode.ide.repoNature` marker) so *File > Import > Existing Projects* on the repo root just works. CAVEAT: a root `.project` overlaps nested bundle projects (Eclipse forbids overlapping projects), so the Hephaestus dev repo itself cannot ship one - auto-discovery (scan workspace projects for `.opencode/`) must carry that case; the root-project path serves user repos without nested Eclipse projects.
4. **Board first-open**: with a shipped `.opencode/tasks` store the Board should be usable immediately after clone+install (ties into reset/new-project actions, see O-002).
