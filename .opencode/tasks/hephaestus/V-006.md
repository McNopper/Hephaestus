User direction 2026-08-26: "we can run in headless mode and can connect and disconnect at any time". Today the engine's lifecycle is bound to the client that spawned it: the stdio MCP server dies with its session and the shutdown hook kills the spawned opencode serve + in-flight jobs - disconnect mid-run kills the run (bookkeeping survives on the ticket). Make the headless engine a daemon: a detached process owning FleetControl (spawned server, jobs, permission queue), with attach/attach-less MCP access so any chat session or Eclipse instance can connect and disconnect freely while runs continue. Also the natural home for the Auto dispatch loop (currently Eclipse-only). Design first (socket/pipe protocol, pidfile, discovery, auth via the generated password, orphan cleanup), then implement. Post-Milestone-V (V-004) - do not start before the validation run lands.
