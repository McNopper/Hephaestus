User report 2026-09-15 (live session): after the chat session planned sprint-2026-09-15, created tickets and moved five tickets through claim/dispatch, the open Board view in Eclipse did not update. The Board already has a TaskStoreWatcher + single-flight refresh + polling (BoardView.java:142) and a manual refresh action, so the gap is somewhere in: watcher not firing for peer writes (the tasks stdio server / fleet workers write the same files), the watched root being a stale preference default instead of the adopted repo store (see O-001 AC-1), or the sprint selector not surfacing a peer-created sprint so the view looks unchanged. Diagnose which, fix, and make peer-written state visible by default - the store is a multi-peer blackboard (AGENTS.md) and the Board is its projection.
