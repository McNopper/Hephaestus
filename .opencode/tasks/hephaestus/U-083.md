Matrix row Java / Arch rules. Today releng/check-architecture.ps1 enforces the BUNDLE graph
(Require-Bundle direction, fixed paths, mojibake) but nothing enforces the PACKAGE level inside bundles:
a board.views class could import fleet internals beyond the seam and no gate would notice.
Add ArchUnit (rules as JUnit) wired into the existing verify gate:
- namespace rule: every package under com.opencode.ide (mojo under com.opencode.ide.mojo)
- bundle-boundary rule: classes may only import packages of bundles allowed by the QUALITY.md graph
  (board->chat/fleet/core/tasks/git/client, chat->core/client, ui->core/client/tools, cdt->core,
  core->client/mcp, fleet->client/git/tasks/tools, mcp->client/tasks/tools, tasks->tools, git->client,
  client/tools->(gson+jdk only)); presentation bundles never imported from below
- no cycles at the bundle level; *.tests fragments never imported by production code
- Eclipse-free layer purity at bytecode level (client/tools/tasks/git/fleet: no org.eclipse.swt/jface/workbench)
ArchUnit imports bytecode from the reactor's target/classes dirs (resolve reactor root at runtime,
never a fixed path). Mechanism precedent: pomDependencies=consider is already set in the parent pom
(how gson reaches client). The test module builds AFTER all bundles in reactor order.
