Rubberduck IA review 2026-09-23 (facts verified): four call sites transform a session id into a view secondary id with THREE different encodings - ServerView/FleetView use replace('%','_'), SessionDetailsView.sanitize strips '%', SessionDetailsView fork->chat uses URLEncoder.encode - while ChatView only resumes when the secondary id startsWith('ses_'). Same session => different secondary ids => duplicate ChatView/SessionDetailsView instances, each with its own submission/fork state. Fix: one opener seam (extend core.context.ChatLauncher to openChat/openDetails), one sanitizer owned by the chat bundle's resume convention; every pane becomes a caller. Also delete FleetView's AUTO_REFRESH_HINT_PROPERTY system-property hack in favor of a real parameter (board->ui edge).
