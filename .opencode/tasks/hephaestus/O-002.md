Product owner, 2026-09-15: "The end user should just use the repository with the given tickets. If the user wants to work on something different, the tickets just need to be deleted."

Deleting tickets = hand-deleting files under `.opencode/tasks/<project>` today. The store natively supports multiple projects side by side (deleting is a choice, not a necessity - other projects keep their history/actuals). Ship proper actions instead of file surgery:

1. **New project** - prompt for a name, scaffold `.opencode/tasks/<name>/` (+ `_meta.json`), switch the Board to it.
2. **Reset project** - explicit confirmation listing what is lost (tickets, actuals, sprint history), then clear the project's store. Must respect cross-project ownership: never touch other projects' reservations, worktrees or fleet slots (the persistent `<id>.project` bindings stay intact for other projects).

Pairs with O-001 (repo-driven self-configuration): a fresh repo clone shows the shipped board immediately; repurposing it for different work is one action, not a file operation.
