Owner requirement 2026-11-14 (chat): things the owner types are requirements or bugs; they must go through the harness (store -> tickers -> workers -> verdicts). The kickoff chat agent does NOT directly implement: its role is intake (register tickets with distilled acceptance criteria), governance (records, epics, escalation) and verification (evidence checks). Direct implementation by the chat agent is a process violation - observed twice on 2026-11-14 (the unified-ticker prototype; the AGENTS.md intake edit) before this requirement landed. Owner suggestion to evaluate: a dedicated intake agent (agent definition) that owns registration so the boundary is enforced by role, not by discipline.
