User direction 2026-09-20: "from my perspective, the fleet should be a tree view." Today FleetView is a flat TableViewer of jobs. Restructure into a TreeViewer hierarchy: engine/wave -> fleet job (ticket) -> worker session -> subagent sessions (v2 parentID nesting) -> console/shell tasks (v2 /api/shell, /api/pty, shell.* events). Every node carries live state: busy decoration + current-action text (last assistant snippet / running tool), tokens+cost rolled up per subtree, and level-appropriate context actions (job: abort/diff/folder/take over; session: watch live in Session Details (U-015); console task: open output in an Eclipse console). Builds on U-015 (watch live), U-024 (daemon jobs as first-class rows - in the tree: first-class NODES with explicit engine addressing, the U-038 lesson), U-026 (V-flow trace). Eclipse reuse per docs/fleet-observability-eclipse-reuse.md: TreeViewer + styled label providers (existing patterns), MessageConsole per task via AgentToolsConsole's IConsoleManager pattern, no Debug-platform/TM-Terminal deps in this slice.
