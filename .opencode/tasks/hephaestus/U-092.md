Owner request 2026-10-12: 'when a subagent is running, one can still inject messages' -
PROVEN TRUE by live probe on our service (2.0.21, 2026-10-12): created a session, posted
POST /api/session/:id/prompt {text, delivery:"steer"}, posted a SECOND prompt while the
first turn was running -> HTTP 200, the injected user message landed MID-TURN and the
assistant reply incorporated it (message order: user, assistant(started), user(injected),
assistant(contains steer text), idle). No interrupt needed.

Already in our codebase (T-005): ChatRequests.promptBody(request, delivery) with
delivery=steer|queue; ChatSessionController.send(msg, delivery); inbox move via
updateInboxItem (steer/queue); ChatView steer/queue actions.

Feature gap to build:
1. Steer RUNNING SUBAGENT sessions (parentID != null) - they are visible in the Server
   view tree but there is no surface to inject into them mid-run (chat opens own sessions).
2. Upstream parity (v2.0.23/24): 'Pending' label for steer messages not yet delivered,
   move-to-queue/undo icons, running-subagent header indicator, '+N working/running'.
3. Correct the client javadoc semantics: 'steer' does NOT interrupt the active run
   (OpencodeClient/ChatSessionController wording says it does; the live probe shows
   mid-turn injection without interrupt).

Version context: latest upstream v2 = 2.0.26, our service pin = 2.0.21; the steering
CONTRACT (delivery param) already works on 2.0.21 (this probe). Upgrade is optional.
