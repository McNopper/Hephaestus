STALE compares updated stamps (StageReadiness: isStrictlyAfter(viaEpic.updatedAt, t.updatedAt)), so any write to an upstream - a comment, a role/epic bookkeeping fix - invalidates its done downstreams (the review hit this on W-006). includeStale defaults to false (DispatchPolicyStore.java:58), so no automatic paid re-runs follow, but the badges mislead, and opting into stale re-runs would re-run work for bookkeeping edits. Options: (A) keep (any write counts). (B) only status/stage/artifact changes count (a dedicated inputs-changed stamp). Recommendation: B. Pairs with U-052.
