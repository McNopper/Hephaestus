Reported live 2026-10-07 in Eclipse: 'Send failed: opencode ses_...: no completed reply within 300s (the server may still be working...)'. Two defects combine: (1) HttpOpencodeClient.awaitReply uses ONE absolute budget (ClientTuning.PROMPT_TIMEOUT, default 5 min) - any healthy turn longer than 5 minutes fails, regardless of activity; (2) the timeout is a plain OpencodeException, but ChatSessionController.isPromptTimeout only recognizes HttpTimeoutException, so the existing late-reply recovery (recoverFromPromptTimeout -> startLateReplyWatcher, already progress-aware) never engages and the user sees a failure. Fix: progress-aware budget (no-progress window REPLY_STALL_WINDOW default 10 min + absolute cap PROMPT_TIMEOUT default raised to 60 min, both env-tunable; any message-list change is progress), a marker exception OpencodeException.ReplyTimeout, and isPromptTimeout recognizes it so the late-reply watcher takes over silently instead of failing.
