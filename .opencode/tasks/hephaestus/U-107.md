T-029 decision (2026-11-10): the id-sanitizing guard is warranted. Evidence: C--001 exists because task_create minted prefix+'-%03d' with id_prefix 'C-' (Trailing dash => double dash). TaskStore.nextId (TaskStore.java ~2095: String.format("%s-%03d", prefix, n)) trusts the prefix blindly. Guard: reject id_prefix values that are blank or end in '-' (Invalid, same class as the stage/priority validations) - rejecting beats silently sanitizing (the caller should know their prefix was wrong). TaskToolProvider task_create passes the prefix through unchanged today. Tests: a create with id_prefix 'C-' is rejected with a clear message; 'W' and 'B' keep working; the C--001 id itself stays valid to read (no migration).
