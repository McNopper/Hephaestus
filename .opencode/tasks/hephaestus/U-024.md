Live finding 2026-09-18: the Fleet view's Session column is blank for ALL daemon-launched jobs - PeerJobReconstructor renders them as external view-only rows by design (F-004), and since the daemon now runs every wave, the column (and Watch live / Abort for those rows) is dead. Root cause: FleetControl.spawn ignores FLEET_DAEMON - the V-006 attach exists only in the stdio path (FleetStdioMain); the board/mcp paths always spawn a per-process engine, so the daemon's jobs are forever 'external'.

Design sketch: (1) a tiny daemon client in the fleet bundle (hello + fleet_jobs/job_details over TCP, like the chat-side python driver) merged into FleetJobsModel as live rows; (2) an abort tool in the daemon's FleetToolProvider (FleetControl.abort path exists engine-side); (3) watch-live either hands the daemon server's credentials through the pidfile-adjacent state or the daemon proxies session reads. Until then the blank column is the visible symptom, not a data loss.
