User direction 2026-09-20 (trigger: JDK upgrade on the host): "we need a feature that we can properly shutdown." Today the pieces exist but are scattered: fleet_waves_stop/fleet_auto_stop only stop admissions, daemon/shutdown is hidden in the TCP protocol (no chat tool, no Board button), in-flight workers die uncheckpointed when the serve is killed, there is no maintenance flag refusing new dispatches while down, and chat-side fleet tools silently target whichever engine the MCP attached to (a waves_stop aimed at the daemon hit the chat's LOCAL engine instead - live 2026-09-20). Feature: ONE shutdown action (chat tool fleet_shutdown + Board button + eclipse/fleet-stop.ps1) that (1) stops waves+auto admissions on the TARGET engine (explicit engine addressing: local vs daemon), (2) checkpoints every in-flight worktree (auto-commit WIP to the task branch BEFORE the serve dies; ticket marked paused, not blocked), (3) gracefully shuts the daemon incl. its spawned serve and removes the pidfile, (4) sets a maintenance flag in .git/opencode-fleet that makes dispatch/auto/waves starts refuse with 'maintenance' and is visible in status tools, (5) prints a shutdown report (stopped, checkpointed, residue pids). Bring-up (fleet-daemon.ps1) clears the flag and lists resumable tickets (branches with WIP checkpoints). Pairs with the pause/resume idea (2026-09-20): pause = checkpoint + hold, resume = re-dispatch continuing the preserved branch - the B-006 reclaim must gain a resume path for branches with unmerged WIP commits.
