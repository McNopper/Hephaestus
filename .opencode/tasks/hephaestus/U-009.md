User direction 2026-09-16: "as we are in eclipse, I want to be able to build, execute and debug C++ applications using an agent... that the agent is then debugging and I see what is going on." The tools already exist (eclipse-build MCP: cmake_configure/cmake_build/ctest_run/run_binary/debug_batch - gdb). The SEAM landed in e817edb (ToolInvocationHub + ToolInvocationListener wired into McpDispatcher, 12 tests: invocation capture, arg summary caps, output tail, listener isolation). Remaining: the Eclipse console surface - an org.eclipse.ui.console-based view subscribing to the hub, one block per invocation with the output tail, so the human watches agent-driven builds/debugs live. Full interactive CDT debug steering (shared breakpoints with the CDT debugger) is explicitly out of scope for this ticket.
