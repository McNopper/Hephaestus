The owner's V-enforcement contract (2026-10-11), made explicit at the doc layers:

1. Every stage CREATES its artifact (requirements/system/architecture/design docs, code+note, tests) at that stage.
2. Top-down coverage is AUTOMATIC: downstream work runs with the upstream definitions delivered, never from agent memory.
3. The harness FORCES the process: no bare stage exits, no self-declared done.
4. Upstream proof = artifact EXISTENCE, not a status label (done-without-artifact = architecture was not done).
5. Send-back ONLY on two triggers: (a) something missing from the previous stage, (b) it needs refactoring/clarification. Otherwise: cover in place, never flow back by reflex.
6. 'Works' is proven on the RIGHT leg - the paired test-* stage. A worker's 'done' is a claim; the gate/reviewer is the verdict.
7. The right leg is a ladder (unit->implementation, component->design, library->architecture, integration->system,
   acceptance->requirements); a failed validation loops HORIZONTALLY to the definition that produced it, a
   missing/wrong definition loops VERTICALLY to the previous stage. Reflect both loops in skills/agents/docs.

This ticket lands the contract in: the 10 software-*/test-software-* skills (per-stage artifact + coverage step + Done block
+ failure routing), the 4 agent files (executor, manifest-author, project-manager, reviewer - worker contract + four-box
acceptance check), and the AGENTS.md V-pipeline section.
Engine-side siblings: U-079 (prompt injection), U-080 (advance gate), U-081 (readiness artifact rule),
U-082 (horizontal loop: tool + prompt routing + review-fail route) - keep wording consistent with them.
