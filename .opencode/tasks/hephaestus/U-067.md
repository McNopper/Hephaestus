Chunk 1 of the U-043 decision (blocked is a state, one state machine). THE semantic core - schema, codec and transitions must land together:
(a) status set gains `blocked`; new nullable `resume_to` field (the status clear-blocked returns to; default sprint-backlog); `blocker` keeps the reason. (b) TaskFileCodec round-trips both; a legacy file with blocked:true and an active status migrates once on read (status=blocked, resume_to=old status, one history entry noting the migration). (c) transitions: task_set_blocked -> status=blocked + resumeTo=previous; task_clear_blocked -> status:=resumeTo; task_send_back -> status=blocked + resumeTo=backlog-of-previous-stage; claim/close-sprint/advance rules keep their invariants (done and paused never blocked - done+blocked becomes structurally impossible, not just linted). (d) StageReadiness BLOCKED kind reads the state. (e) doctor: keep sprint-but-product-backlog, drop done-but-blocked (impossible), keep unparsable/artifact checks. Tests: store semantics, codec migration, dispatch tests (23-tool count unchanged), readiness.
