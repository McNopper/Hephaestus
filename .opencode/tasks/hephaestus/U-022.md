User direction 2026-09-18: 'a project manager agent or the tool itself just runs waves on a regular basis; normally the end user does not have anything to do unless there is a blocked element.' The pieces exist (auto-dispatch loop drains a sprint; readiness gates what runs; blocked tickets bubble) - missing: wave-to-wave planning (backlog -> next wave when the current drains), a daemon-attached always-on mode, and the explicit NEEDS-HUMAN escalation surface. Implementation pointers: dispatch/AutoDispatch + DispatchScheduler (fleet bundle) drive the loop; BoardView readiness badge pattern (U-018) extends to NEEDS-HUMAN count; wave planning can reuse the PM planning skill logic minimalistically (priority order + readiness filter).
