Observed 2026-09-23 after the overnight opencode upgrade to v2.0.14 + a fresh shared-service spawn (Eclipse started 05:58:27, service.json written 05:58:34): the repo-scoped MCP list showed fleet CONNECTED and FleetStdioMain was running, even though opencode.json keeps "enabled": false (fleet must stay off deliberately - token eater; user direction 2026-09-22). Re-disconnected via POST /api/experimental/mcp/fleet/disconnect?location[directory]=... - state in-memory only, no MCP state file under ~/.local/state/opencode, so a service restart may re-arm it again.

Either 2.0.14's MCP init (on client attach) connects all configured servers ignoring enabled:false, or some client explicitly connected it. Yesterday on 2.0.10/2.0.11 a fresh spawn did NOT connect fleet.
