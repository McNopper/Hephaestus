Owner observation 2026-10-14 (first TUI session): a SUBAGENT asked him a question and it
was visible there. In our harness this must be equally visible - and since several agents
can ask at once, a COLLECTED list of pending questions is the target.

What already exists (review before building - much may only need aggregating):
- fleet: PermissionQueue (asked/replied, dedup by permission id), the chat-triggerable
  fleet_fleet_permissions (list) / fleet_fleet_permissions_answer (once/always/reject)
- board: FleetPermissions rows join pending asks with jobs by session (FleetPermissionsTest)
- ui Background view: pendingAsksRenderWithTheirDisplayLine (BackgroundModel/ChatPermissions)
- chat: ChatPermissionAdapter renders asks for THE OPEN session only
- client: PermissionEvents parses permission.asked/replied SSE; reply route exists
  (POST /session/:id/permission/{requestID}/reply); GET /permission/request lists asks live

The gap:
1) IN-SESSION visibility: when a SUBAGENT (parentID set) raises a question/permission, it
  must surface in the surfaces where the parent session is watched (session details,
  background list, server view row) - today the chat only shows asks of its own session.
2) COLLECTED LIST: one place shows ALL pending questions across sessions/agents (several
  at once), each with agent/session attribution + age, answerable inline (same
  once/always/reject semantics), with a count badge + notification so nothing waits
  silently (an unanswered ask stalls a worker - tie into the watchdog/pause behavior).
3) TUI-parity language: steered/queued and question states read like the TUI's.

Design note: prefer ONE questions pane (or a Server-view category) fed by
GET /api/session/:id/permission + the SSE asked/replied events over per-view polling.
