User direction 2026-09-20: "in opencode v2 it is easy to send something to the background - we need this as well!" (Roadmap open item, previously unticketed.) v2 pushes a session to the background via POST /api/session/:id/background; background sessions are ordinary sessions on the event stream. Expose in Eclipse: (1) chat: a send-to-background action on the active session - it keeps running detached, events keep flowing; (2) a background-tasks surface (Server view section, or the engine node of the Fleet tree U-040) listing background sessions with activity state; (3) bring-back: reattach a background session into the chat with full history; (4) fleet: dispatch can launch straight INTO background mode so the Fleet tree is the observation surface instead of a foreground session. Reuse: the existing busy-icon state (U-007), the shared client envelope, Session Details as the drill-down.
