The TUI surfaces permission asks with an answer flow (once/always/reject + feedback). The harness has the backend (PermissionQueue/FleetPermissionBridge/fleet_permissions*, ChatPermissionSink seam, and now the client's poll-based listPermissionRequests = GET /api/permission/request) and a board-side dialog (FleetPermissionsDialog), but NOTHING in the chat surface. Event streams are per-process and not replayed, so asks raised while no listener was attached are invisible - the reconnect recovery read path is part of this ticket (rubberduck F-7).
