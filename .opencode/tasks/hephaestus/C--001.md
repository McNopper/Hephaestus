Live finding (2026-09-15, session ses_fc99f8e76ffe): in the Eclipse chat, the reply to one message rendered fine with meta=zai-coding-plan/glm-5.3, and the NEXT message in the same session was sent with meta=ollama/qwen3.5-4b-32k and rendered "assistant bubble rendered (0 chars)" (see workspace .metadata .log). Two defects: (1) the per-send model flipped from the selected glm-5.3 back to the spawned server's default (ollama qwen 4b, 32k ctx) between sends - either the selector state resets or the send path falls back to the server default; (2) ChatPage.__setAssistantText with empty text wipes the bubble body (body.innerHTML=""), so any text that already streamed vanishes - the user sees the answer disappear / "markdown never resolves". An empty final reply must finalize the streamed raw text instead (chat.js __stopStream already does this - reuse that path) plus surface an error notice. Also pin the repo default model (opencode.json) so spawned servers match the TUI experience - fits O-001.
