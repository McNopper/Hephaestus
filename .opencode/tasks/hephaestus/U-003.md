User direction 2026-09-15 (back in the TUI after live-testing the Eclipse chat): the Eclipse chat should match the TUI's streaming experience - colors, resolved markdown while streaming, message queueing and cancel. Current state: the chat page (eclipse/components/chat-web/web/chat.js) renders markdown/markdown tables, syntax-highlighted fences (hljs, theme-switched), KaTeX math and mermaid diagrams in FINAL renders only; during streaming the bubble shows raw monospace text (stream-raw) until __stopStream/__setAssistantText finalizes it - long generations stare at unformatted pipes/asterisks. The Abort action exists (toolbar + Ctrl+Alt+Shift+A, ChatView.abortRequested) but is undiscoverable - no inline Stop button. Message queueing does not exist: the input has a single Send path, no pending queue while generating. Scope: (1) progressive markdown rendering during streaming (render-on-delta, throttled; keep the stream-done guard semantics); (2) inline Stop control near the input while generating; (3) TUI-style queue: type+Enter while generating enqueues, pending messages visible/editable, auto-send on completion. Follow-up note: history loads render every bubble eagerly (a 1615-entry session rendered in one go) - consider lazy/virtualized history as a separate follow-up if it stays slow.
