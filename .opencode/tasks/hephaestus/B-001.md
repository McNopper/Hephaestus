Found by the FIRST GitHub Actions run (H-001 CI, run 33028238280): GitWorktreeManager.list() matched worktree paths by startsWith(.git/opencode-fleet), but git reports worktree paths in its canonical form while the JVM handed Java-lexical paths - on Windows runners the temp dir is C:\Users\RUNNER~1 (8.3 short name) vs git's C:\Users\runneradmin, so list() returned [] and remove()/mergeBack() failed with 'No fleet worktree for task'. Local machines without short-form temp paths never saw it. Production impact beyond CI: any repo under an 8.3/subst/symlink path silently loses fleet worktree discovery.
