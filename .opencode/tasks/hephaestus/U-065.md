Reported live 2026-10-07 while testing the deployed build: 'columns should be used like in Progress; in V-Model and Epic just a list of rows at the moment. Sometimes icons are used, sometimes not - inconsistent.' Facts (BoardView.java at HEAD): the Progress (flat) layout renders REAL columns per card (status glyph | type icon | title | points, sortable - createTicketViewer + the 2026-09-18 user direction noted at :746-751), while V-model stage tables (:687-699) and Epic swimlanes (lane header at :450, cards via statusPrefixedLabels) render ONE composed-string column. Group headers are text-only everywhere (lane :450, status :621, stage :667) while cards and toolbar actions carry icons.

Do: (1) V-model stage tables and Epic lane tables render the SAME real sortable columns as Progress - reuse the column builder; the status glyph is informative in all modes. (2) Every group header carries its kind's glyph consistently (status columns: the status icon; stage columns: the stage marker; epic lanes: an epic marker) - reuse the existing icon set (icon(...) helper; type-*/status glyphs); if no epic icon exists, reuse the closest existing one, do not generate new art. (3) Remove the composed-string card path once unused, or pin with a comment where it is genuinely needed. Files: BoardView.java and its label providers/model in com.opencode.ide.board + com.opencode.ide.board.tests; no other bundle.
