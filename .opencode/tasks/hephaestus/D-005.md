Owner question 2026-11-09: 'is the fleet feature still required - it sounds like Claude Code/opencode do this automatically now?' Answered by the research report (artifact): the fleet's execution primitives (worktree isolation, model selection, claim mechanics, per-run budgets, workflow watchdogs) are now native in opencode and/or Claude Code; the durable Hephaestus core is (1) the task store as the cross-host coordination blackboard, (2) the V-model pipeline semantics, (3) the budget-admission pump over a prioritized backlog, (4) the Eclipse host integration. DECISION: adopt upstream mechanics as they land, never rebuild them; first adoption chunk U-106 (FleetRunner onto the server worktree APIs); standing watch: Claude Code agent-teams durability, an upstream merge/PR worktree strategy, and any supported unattended multi-ticket composition (re-run the research on those events).
