Fleet redundancy review 2026-11-09 (docs/fleet-redundancy-review-2026-11.md): opencode's v2 server exposes worktree CRUD natively (GET/POST/DELETE /api/worktree, worktree.refresh, worktreeReset; SDK worktree.create/refresh/remove 'with the recorded strategy') - the routes live in the experimental HTTP group, and they overlap FleetRunner's direct git-worktree handling, so this is the adopt-and-remove class of the experimental policy. Adopt: spawn dispatched workers in worktrees created via the server API; reap via worktree.remove (force where unmerged residue is real). KEEP ours: merge-back (no native merge verb exists - reset discards, remove deletes) and the settle/reap bookkeeping that keeps the store authoritative. Acceptance: FleetRunner makes zero direct `git worktree` shell-outs for spawn/remove; a test pins the API-driven lifecycle; docs (fleet-quickstart, feature matrix) updated in the same change.
